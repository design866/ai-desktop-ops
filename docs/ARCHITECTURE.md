# 架构：为什么切成这样

一个做"应用启动器"的东西，最省事的写法是把 spawn 直接塞进界面里。App Dock 没有。
下面每条取舍都对应一个具体的坑。

```
┌─────────────────────────────┐        ┌──────────────────────────────┐
│  宿主桌面应用（侧栏面板）    │        │  hub.py  127.0.0.1:7777      │
│                             │        │                              │
│  plugin.js                  │  HTTP  │  · 读 apps.json（热加载）    │
│   ├ 拉 /api/state   ────────┼───────▶│  · TCP 探活 / 进程名比对     │
│   ├ 渲染条目                │        │  · spawn 子进程（cmd/exe）   │
│   ├ POST /api/start ────────┼───────▶│  · 吐 JSON + 自带页面        │
│   └ 裸 iframe 嵌 web 应用   │        └───────────┬──────────────────┘
│                             │                    │ spawn
└─────────────────────────────┘                    ▼
                                        ┌──────────────────────────┐
                                        │ 你的本地服务 / 独立程序   │
                                        │ :7480 :7481 :8888 …      │
                                        └──────────────────────────┘
```

---

## 1. 能力放在 hub，界面只读

**取舍**：插件不 spawn，一切启动走 `POST /api/start/<id>`。

**为什么**：
- 面板代码跑在宿主渲染进程里，拥有页面的全部权限（同源 fetch、`nodeIntegration` 视宿主而定）。
  给它 spawn 等于「界面里的一段 JS 能起任意进程」——出一个 XSS 就是命令执行。
- Hub 是一个**可审计的边界**：6 个端点、只能起 `apps.json` 里登记过的 id，
  不接受任意命令字符串。
- 顺带得到：插件崩了应用还在跑，重启宿主不用重启服务。

**代价**：多一个常驻进程、多一层 HTTP。值得。

---

## 2. 状态是拉，不是推

**取舍**：插件每 5 秒 `GET /api/state`，不用 WebSocket/SSE。

**为什么**：
- 状态源是"端口通不通 + 进程在不在"，本身就是轮询语义。
- Hub 侧 `tasklist` 有 3 秒缓存，`/api/state` 稳态 ~45ms，5 秒一次可以忽略。
- 单向拉取不需要重连逻辑：hub 挂了面板变灰，hub 起来自动恢复。

**代价**：最多 5 秒的延迟才看到"刚起来的应用变绿"。启动时前端另外做 45 秒的快速轮询补偿。

**冷启教训**：首次 `/api/state` 要探全部端口，本机 5 条 ~1.6 秒。所以插件里的超时必须
给到秒级 —— 用 300ms 判超时会得到"hub 没起来"的假结论。

---

## 3. 内嵌用裸 `<iframe>`，不用沙箱组件

**取舍**：`iframe` 不加 `sandbox`，也不加 `allow-same-origin` 之类的属性修饰。

**为什么**：
- 宿主 SDK 常带一个「安全沙箱 iframe」组件，默认剥掉 `allow-same-origin`。
  一旦剥掉，guest 就是 opaque origin：
  - `localStorage` / `indexedDB` 直接抛 `SecurityError`
  - Vite/React 的 SPA 在 bootstrap 阶段就崩 → 白屏
- 这是"安全默认值"和"能用"之间的真实冲突。App Dock 的选择是：
  **只在 iframe 里放你自己本机跑的服务**，用"来源可控"换"能跑"。

**代价**：guest 与宿主同源信任级别。所以 `README` 里明确写了：别把外网站填进清单。

**替代方案**（如果宿主支持）：`webview` 标签 + `partition`，能同时拿到隔离与同源。
插件留了这个位置，但默认走 iframe —— 兼容性优先。

---

## 4. 清单外置 + 占位变量

**取舍**：应用条目不在代码里，在 `apps.json`；路径写成 `{LOCALAPPDATA}` 这类占位。

**为什么**：
- 一份代码跨机器：家里台式机和笔记本用同一份仓库，`apps.json` 各自维护。
- 存盘即生效：加一条应用不用重启 hub（不用重启宿主，面板 5 秒后自己刷新）。
- 天然去隐私：仓库里的示例清单不含任何本机绝对路径和真实用户名。

**代价**：多一个文件要维护，"复制示例再改"是必需的安装步骤。

---

## 5. 常驻是行为，不是样式

**取舍**：`collapsible: false` **加上** 6 秒一次的看门狗。

**为什么**：
- 只声明 `collapsible:false` 挡不住所有路径：快捷键、布局重置、宿主的"重置面板"、
  某些版本的拖拽误触，都可能让面板消失且不再回来。
- 看门狗的逻辑很短：`if (!host.paneVisibility(scopedId)) host.undismissPane(scopedId)`。
  这一步把"声明式意图"变成"可观测的收敛行为"。

**代价**：用户永远关不掉这个面板。这是需求（"固定在侧栏，变成宿主的一部分"），
但对不想要它的人不友好 —— 所以面板里给了折叠条目的能力，而不是关面板。

---

## 6. 探活的两种语义

| kind | 判据 | 为什么 |
|---|---|---|
| `web` | `connect(127.0.0.1, port)` 成功 | 与 HTTP 状态码无关：服务返回 500 也是"在跑"，用户要的就是"它活着" |
| `native` | `tasklist` 里存在同名 `.exe` | 独立窗口程序没有稳定端口，只能看进程 |

`native` 的比对是**文件名级**：`Some Editor.exe` 在任何目录跑都算在跑。
够用且便宜（3 秒缓存的 `tasklist`），代价是同名不同程序会误判 —— 罕见，接受。

---

## 7. 可观测性：一行指纹文件

`GET /api/ping?src=<src>&pane=<0|1>&n=<条数>` 会把这次访问追加到 `logs/plugin-alive.txt`。

**为什么不是打日志到控制台**：宿主渲染进程的 `console.log` 通常不进日志文件，
只有 `console.error`/异常会。所以：

- 插件 `register()` 时 `console.error('[app-dock] loaded <ISO>')` —— 证明"插件被加载"
- 插件拿到数据后 `fetch(.../api/ping?pane=1&n=<N>)` —— 证明"面板渲染了 **且** 成功跨源取到了数据"

这两条区分了三种坏状态：插件没加载 / 加载了但面板没渲染 / 渲染了但拿不到数据。
排障时先看 `plugin-alive.txt` 有没有 `pane=1`，能省掉一轮瞎猜。

---

## 8. CORS 由 hub 兜

插件在宿主的 origin 下（`file://` 或宿主自定义协议），fetch `127.0.0.1:7777` 是跨源。
所以 hub 统一返回：

```
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, POST, OPTIONS
Access-Control-Allow-Headers: Content-Type
```

并实现 `do_OPTIONS` 回预检。`*` 在这里是可接受的风险：服务只监听 `127.0.0.1`，
且端点只认清单里登记过的 id。

---

## 9. 子进程管理

- `cwd` 显式传给 `Popen`，不依赖 hub 的当前目录
- `stdin=PIPE`（web 服务常读 stdin 判活，继承来的句柄会出怪问题）
- Windows 上 `creationflags=0x8|0x200`（`DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`）
  —— hub 被关掉时子进程不至于跟着一起死
- **结束 hub 时不能 `taskkill /T`**：会把整棵子进程树带走，用户的 7 个服务全灭

---

## 未做（有意）

- **不做应用市场/远程清单**：清单来自本地文件，不 fetch 任何远端 —— 少一个攻击面
- **不做进程守护/自动重启**：那是 supervisor 的活，混进来会让"停止"语义变糊
- **不做权限系统**：本机单用户工具，加 ACL 是自欺
- **不做跨平台端口探测之外的抽象**：Windows 优先（`tasklist`），Linux/macOS 的
  native 探活需要替换 `running_exes()`，接口留好了，一行实现
